# 外洩閘門的自我測試

閘門（`leak_check.py`，住在私有研究工作區）比對公開 repo 的每一行與受授權限制來源的每一行，
命中就不准推。**閘門本身也要被測試**：一個永遠回報「0 命中」的閘門，和沒有閘門是同一回事，
而且更糟——它會讓人以為自己被保護著。

## 測什麼

一正一反，兩邊都要成立：

| 方向 | 測法 | 預期 |
|---|---|---|
| 反（不能誤擋） | 一份只有自己寫的中文說明的文件 | 0 命中 |
| 正（一定要擋） | **每一份來源**各挑一行原文植入假文件，大小寫與前後空白都改過 | 每一份都命中 |

正向那邊逐來源測是重點。只抽一行測，證明的是「閘門對某一份來源有效」；
新來源加進來（M4 的 Watcom 就是一例）沒被覆蓋到也看不出來。
樣本挑該來源最長的那一行，避開通用字串。

## 怎麼跑

```sh
docker run --rm --network none -u "$(id -u):$(id -g)" \
  -v ~/cht/borland:/p:ro retro-runtime-study-tools:1 \
  python /p/tools/leak_check.py --self-test /p/vendor
```

預期輸出的形狀（2026-09-18，八份來源）：

```
  (vendor 根目錄的產物)      植入原文 → 命中
  borland-crtl-2.0     植入原文 → 命中
  dmx                  植入原文 → 命中
  dsmi                 植入原文 → 命中
  msvc-1.0-crt         植入原文 → 命中
  msvc-2.0-crt         植入原文 → 命中
  watcom-6.5           植入原文 → 命中
  watcom-7.0           植入原文 → 命中
self-test 通過：乾淨文件 0 命中；8 份來源各植入一行都被抓到（vendor 可比對行 95637 條）
```

任何一行變成「沒有被抓到」，或來源數量比預期少，就是閘門破了——**先修閘門，不要推**。
測試資料是臨時產生的（植入的原文只存在於容器內的暫存目錄），不落地、不進任何 repo。

## 閘門抓不到什麼

這是下限檢查，不是證明。它比對的是「正規化後完全相同的行」，所以：

- **改寫過的原文抓不到**：換變數名、重排順序、把兩行併成一行，都躲得掉。
- **短行與通用行不列入比對**（正規化後少於 24 個字元，或像 `#include <stdio.h>`、`}` 這種），
  否則每篇文章都會誤報。
- **翻譯過的內容抓不到**：把英文註解翻成中文寫進文章，閘門不會有反應。

所以閘門擋的是「手滑貼上」，真正的防線是書寫規則：只寫機制、符號名、參數意義與演算法步驟，
要示意就用自己寫的虛擬碼。

## 為什麼 open-watcom-v2 不在比對來源裡

比對來源是私有工作區的 `vendor/`，語意是「禁止散布、必須被擋下的來源」。
open-watcom-v2 的授權（Sybase Open Watcom Public License 1.0）允許引用，
它放在私有工作區的 `refs/` 底下，不在 `vendor/`，所以閘門不會拿它來比對。

這樣安排的好處是**閘門的邏輯一行都不用改**。原本的規劃是讓閘門替 open-watcom 的引用開後門
（例如「帶出處註記的區塊放行」），那會在唯一一道機械防線上開一個由人判斷的缺口。
換個落點就不需要了。

引用 open-watcom-v2 的規則另外寫在 `CLAUDE.md`：片段要短、每段標授權與固定 commit 的行號連結、
不拿它當 1988–1993 年出貨版的證據。
